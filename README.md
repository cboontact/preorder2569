# ระบบสั่งซื้ออุปกรณ์การเรียน — โรงเรียนจอมทอง

เปลี่ยนระบบเดิมเป็น **Next.js 16 + TypeScript + Tailwind CSS 4** ทั้งหน้าเว็บและ API ใช้ **Cloudflare Workers + D1** ผ่าน OpenNext ไม่มี PHP ใน runtime ใหม่

## การใช้งาน

- `/` ค้นหานักเรียน เลือกอุปกรณ์ภายในงบ 260 บาท ตรวจสอบและยืนยันคำสั่งซื้อ
- `/history` เลือกภาคเรียน ตรวจสอบคำสั่งซื้อและพิมพ์ใบสั่งซื้อ
- `/admin` เข้าสู่ระบบผู้ดูแล ดูภาพรวม คำสั่งซื้อ สรุปอุปกรณ์แยกห้อง จัดการสินค้า นักเรียน ครูที่ปรึกษา และช่วงเปิด–ปิดรับของแต่ละภาคเรียน
- `/api` Next.js Route Handler ที่เชื่อมต่อ D1 และตรวจสอบข้อมูลบนเซิร์ฟเวอร์
- `/index.php` เปลี่ยนเส้นทางมายัง `/` สำหรับลิงก์เดิม

## คู่มือใช้งานล่าสุด

- นักเรียนเปิด `/` กรอกเลขประจำตัว 5 หลัก เลือกอุปกรณ์ และกดยืนยันคำสั่งซื้อ หากซื้อไม่ครบงบต้องติ๊กยอมรับการเสียสิทธิ์ส่วนที่เหลือ
- หน้า `/history` ใช้ตรวจสอบและพิมพ์ใบสั่งซื้อ โดยแสดงภาคเรียน เลขออเดอร์ เลขที่นักเรียน ครูที่ปรึกษา รายการ และยอดเงินตรงกับคอลัมน์รวม
- เมนูผู้ดูแลใช้ชื่อ **เข้าสู่ระบบ ครูที่ปรึกษา / แอดมิน** ผู้ดูแลสูงสุดเข้าภาพรวม คำสั่งซื้อ สินค้า นักเรียน ครูที่ปรึกษา และภาคเรียนได้ ส่วนครูเห็นเฉพาะภาพรวมกับคำสั่งซื้อของห้องที่ได้รับมอบหมาย
- หน้าคำสั่งซื้อและจัดการนักเรียนจะยังไม่อ่านรายชื่อหรือคำสั่งซื้อจนกว่าจะเลือกตัวกรองครบ หรือพิมพ์คำค้นแล้วกด Enter/ค้นหา เพื่อลดการอ่าน D1
- ภาพรวมแสดงทุกชั้นก่อน สามารถกรองระดับชั้นในตารางสรุปแยกห้องได้ ห้องที่ยังสั่งไม่ครบจะไฮไลต์สีแดง ห้องที่ครบแล้วเป็นสีเขียว และรายงานพิมพ์มียอดรวมท้ายแต่ละห้องกับยอดรวมทั้งหมด
- เลขที่นักเรียนคำนวณใหม่อัตโนมัติแยกตามห้อง โดยเรียงนักเรียนชายก่อน แล้วเรียงเลขประจำตัวน้อยไปมาก การเพิ่ม ลบ หรือย้ายห้องทำให้เลขที่เลื่อนตามทันที
- รายการคำสั่งซื้อเรียงตามชั้น ห้อง และเลขที่นักเรียน ตารางรองรับหน้าจอมือถือด้วยการเลื่อนแนวนอนภายในกรอบ และหัวตาราง/ปุ่มใช้ไอคอน Font Awesome
- โลโก้โรงเรียนใช้ทั้งในใบสั่งซื้อ รายงาน และไอคอนแท็บเว็บ

กำหนดหนึ่งคำสั่งซื้อต่อนักเรียนต่อภาคเรียนและงบ ม.ต้น/ม.ปลาย 260 บาท เซิร์ฟเวอร์อ่านราคาและชื่ออุปกรณ์จากฐานข้อมูล ไม่เชื่อราคาจากเบราว์เซอร์ บันทึกคำสั่งซื้อพร้อมรายการย่อยใน transaction และป้องกันสั่งซ้ำพร้อมกันด้วย UNIQUE constraint

บัญชีผู้ดูแลสูงสุดใช้ชื่อ `cboonta` ชื่อ นายชลนที บุญทา และเป็นครูที่ปรึกษา ม.3/4 ตามที่ผู้ใช้กำหนด โดยเก็บรหัสผ่านเป็น Cloudflare Secret (`ADMIN_PASSWORD`) แทน source code ใช้ HttpOnly/SameSite cookie, session timeout 30 นาที และจำกัดการเข้าสู่ระบบผิด 5 ครั้งใน 5 นาที

## พัฒนาในเครื่อง

ใช้ Node.js 22 ขึ้นไป (ทดสอบด้วย Node.js 24)

```bash
npm ci
cp .dev.vars.example .dev.vars
# กำหนด ADMIN_PASSWORD ใน .dev.vars สำหรับเครื่องที่เพิ่งติดตั้ง
npm run db:local
npm run dev
```

เปิด http://localhost:3000 ข้อมูล local แยกจากข้อมูลจริงบน Cloudflare เครื่องที่เปลี่ยนระบบครั้งนี้มี `.dev.vars` พร้อมใช้งานแล้ว ไม่ต้องคัดลอกทับ

## เมนูจัดการและสิทธิ์ครู

- ผู้ดูแลสูงสุด: เพิ่ม/แก้ไข/ลบนักเรียน และเพิ่ม/แก้ไข/ปิดใช้งาน/ลบบัญชีครูที่ปรึกษา รวมถึงตั้งรหัสผ่านใหม่และกำหนดชั้น/ห้อง
- ครูทั่วไป: เข้าทาง `/admin` และเห็นเฉพาะจำนวนผู้สั่งซื้อ ยอดรวม และสรุปจำนวนอุปกรณ์ของห้องที่ปรึกษาของตนเอง ไม่ได้รับข้อมูลรายบุคคลหรือเมนูจัดการ
- API ตรวจสอบบทบาทและห้องจากฐานข้อมูลทุกครั้ง ไม่ใช้บทบาทหรือห้องที่ผู้เรียกส่งมา ครูไม่สามารถเรียกคำสั่งจัดการหรือข้อมูลนักเรียนผ่าน API ขณะเข้าสู่ระบบได้
- นักเรียนยังใช้หน้าค้นหาและสั่งซื้อสาธารณะตามรูปแบบเดิม
- การแก้ไขบัญชีครูจะยกเลิก session ของครูนั้นทันที บัญชีผู้ดูแลสูงสุดไม่สามารถลบหรือปิดใช้งานได้จากเมนูครู
- รายงานครูอ้างอิงชั้น/ห้องปัจจุบันของนักเรียน ใบสั่งซื้อเดิมเก็บชื่อและห้อง ณ วันที่สั่งซื้อไว้ นักเรียนที่มีคำสั่งซื้อยังลบไม่ได้จนกว่าจะยกเลิกคำสั่งซื้อ
- รหัสผ่านครูจัดเก็บเป็น PBKDF2-SHA256 พร้อม salt แยกต่อบัญชี ไม่ส่ง hash กลับไปยังเบราว์เซอร์ รหัสผู้ดูแลสูงสุดยังใช้ Cloudflare Secret เดิม

`0003_staff.sql` เพิ่มตารางบัญชีครูและข้อมูลผู้ดูแลสูงสุด โดยไม่แก้ข้อมูลนักเรียนเดิม

## ซื้อไม่ครบงบและการยืนยันเสียสิทธิ์

- ยอดเกินงบ: ระบบไม่อนุญาตทั้งหน้าเว็บและ API แม้ส่งค่ายืนยันเสียสิทธิ์มา
- ยอดเท่างบ: ยืนยันคำสั่งซื้อได้ตามปกติ
- ยอดต่ำกว่างบ: ต้องติ๊กยืนยันว่า “หากซื้อไม่ครบงบประมาณ จะเสียสิทธิ์ในส่วนที่เหลือ” ก่อนกดสั่งซื้อ โดยแสดงจำนวนเงินที่จะเสียสิทธิ์อย่างชัดเจน
- ช่องยืนยันไม่ถูกเลือกไว้ล่วงหน้า และจะถูกรีเซ็ตทุกครั้งที่เปิดหน้าตรวจสอบคำสั่งซื้อใหม่
- API `submitOrder` รับ boolean `true` เป็น argument ลำดับที่สามสำหรับการยืนยันยอดต่ำกว่างบ พร้อมบันทึก `unused_budget_acknowledged` และเวลายืนยันลงในรายการสั่งซื้อ
- ใบสั่งซื้อแสดงจำนวนเงินส่วนที่เสียสิทธิ์และการรับทราบ การยืนยันนี้ไม่อนุญาตให้ซื้อเพิ่มเป็นคำสั่งซื้อที่สอง

`0004_unused_budget_ack.sql` เพิ่มช่องบันทึกการยืนยัน คำสั่งซื้อเดิมไม่ได้ถูกตีความย้อนหลังว่านักเรียนเคยให้การยืนยันแล้ว

`npm run test:api` ทดสอบกติกางบทั้งสามกรณี การเก็บหลักฐานยืนยัน การแก้ไข/ลบนักเรียน การจัดการครู การเปลี่ยน/ปิดบัญชี และการแยกสิทธิ์ระหว่างห้องและระดับชั้นบน D1 ในเครื่อง

## ภาคเรียนและช่วงเปิด–ปิดรับ

ผู้ดูแลสูงสุดเข้าที่ `/admin#terms` เมนู **ภาคเรียน / เปิดรับ** เพื่อ:

1. เพิ่มหรือตั้งค่าปีการศึกษา (พ.ศ.) และภาคเรียนที่ 1 หรือ 2
2. กำหนดวัน–เวลาเปิดและปิดรับ **เวลาไทย** พร้อมข้อความแจ้งนักเรียน
3. เลือกอนุญาตรับคำสั่งซื้อตามช่วงเวลา แล้วบันทึก
4. สำหรับภาคเรียนใหม่ กด **ใช้เป็นภาคเรียนปัจจุบัน** เพื่อเริ่มใช้สิทธิ์ของภาคเรียนนั้น เปิดรับได้ครั้งละหนึ่งภาคเรียน

หยุดรับชั่วคราวได้ทันที และเปิดกลับได้ภายในช่วงเวลาที่กำหนด ระบบรับตั้งแต่เวลาเปิด และปิดทันทีเมื่อถึงเวลาปิด เช่น ต้องการรับจนจบวันที่ 30 ของเดือนที่มี 30 วัน ให้กำหนดปิดวันที่ 1 เดือนถัดไป เวลา 00:00

หน้าเว็บแสดงกำหนดเวลาและสถานะ อัปเดตจากเซิร์ฟเวอร์ทุก 30 วินาทีและตรวจนาฬิกาทุกวินาที API และ database trigger ตรวจซ้ำขณะบันทึกเพื่อป้องกันการสั่งนอกช่วงเวลา ตะกร้าจากภาคเรียนเก่าจะต้องค้นหานักเรียนใหม่ก่อนยืนยัน ไม่ถูกย้ายเข้าภาคเรียนใหม่โดยเงียบ ๆ

นักเรียนสั่งได้หนึ่งครั้งต่อภาคเรียน หน้า `/history` และรายงานผู้ดูแลเลือกดูย้อนหลังได้ ครูทั่วไปเลือกดูสรุปย้อนหลังได้เฉพาะห้องของตนเองและตั้งค่าภาคเรียนไม่ได้

`0005_terms.sql` เก็บคำสั่งซื้อเดิมทั้งหมดใน **ข้อมูลเดิม (ยังไม่ระบุภาคเรียน)** โดยคงสถานะเปิดรับและยังไม่กำหนดวันปิด ผู้ดูแลควรตั้งค่ารายการนี้หากทราบภาคเรียนของข้อมูลเดิม หรือเพิ่มภาคเรียนใหม่แล้วเลือกใช้ ระบบไม่ได้เดาปีการศึกษาหรือกำหนดวันปิดรับให้เอง

ทดสอบเวลาเปิด/ปิดที่จุดตัด การแปลงเวลาไทย ภาคเรียนซ้ำ สิทธิ์จัดการ การหยุดรับ ตะกร้าเก่า การสั่งคนเดิมในภาคเรียนใหม่ รายงานย้อนหลัง และ database trigger บน Workers/D1 ในเครื่องแล้ว สคริปต์ทดสอบคืนภาคเรียนปัจจุบันและล้างเฉพาะข้อมูลทดสอบเมื่อเสร็จ

`scripts/prepare-teachers-import.py <source.csv> <output.sql>` สร้าง SQL นำเข้าแบบ INSERT เท่านั้น พร้อมตรวจบัญชีซ้ำและ hash รหัสผ่าน ส่วน `scripts/verify-teachers-import.mjs <teachers.csv> <students.csv>` ตรวจข้อมูลบัญชีและห้องที่ปรึกษาบนระบบจริง รวมถึงทดลองเข้าสู่ระบบด้วยบัญชีตัวอย่างทุกระดับชั้น บัญชีที่มีตัวพิมพ์ใหญ่ และบัญชีที่ดูแลหลายห้อง สคริปต์ไม่แก้ข้อมูลธุรกิจ

## คำสั่งซื้อสำหรับครูที่ปรึกษา

ครูมีเมนูภาพรวมและคำสั่งซื้อในห้อง ดูรายละเอียด พิมพ์ใบสั่งซื้อ และสรุปอุปกรณ์ตามห้องได้ API adminGetOrders จำกัดทั้งคำสั่งซื้อและรายการสินค้าตามห้องปัจจุบันของนักเรียนที่ตรงกับ staff_advisor_rooms ของบัญชี รองรับหลายห้องและเลือกภาคเรียนย้อนหลังได้ การยกเลิกยังจำกัดเฉพาะผู้ดูแลสูงสุด

ทดสอบบน Workers/D1 local ด้วยคำสั่งซื้อจำลอง: ห้องเดียว หลายห้อง การปลอมบทบาท นักเรียนย้ายห้อง และการปฏิเสธการแก้ไข/ยกเลิกของครู ผ่านแล้ว

ใบสั่งซื้อและรายงานสรุปตามห้องมีโลโก้โรงเรียนและชื่อครูที่ปรึกษาทุกคนที่เปิดใช้งานตามชั้น/ห้องในใบสั่งซื้อ โดยดึงจากการมอบหมายครูปัจจุบัน (ไม่ใช่ประวัติการมอบหมายย้อนหลัง) หากยังไม่มีครูแสดงข้อความว่ายังไม่ระบุครูที่ปรึกษา
